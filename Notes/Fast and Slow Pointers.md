
# DSA PATTERN 3 — FAST & SLOW POINTERS
## Recognition → Algorithm → Variations → Interview Problems

> Goal: Recognize when Fast & Slow Pointers can solve a problem, derive the algorithm, and adapt it to variations.

---

# 1. THE CORE IDEA

Use two pointers that move through the same sequence at different speeds.

```text
SLOW → moves 1 step at a time
FAST → moves 2 steps at a time
```

Why is this useful?

- If the sequence ends, FAST can tell us when we have reached the end.
- If the sequence contains a cycle, FAST can eventually catch SLOW.
- Their positions can reveal useful information, such as the middle or cycle entrance.

**Important:** Fast & Slow Pointers is not limited to linked lists. It also works on sequences generated by repeatedly applying a function, such as the Happy Number problem.

---

# 2. HOW TO RECOGNIZE THE PATTERN

Look for these clues in the problem statement.

| Problem clue | Why Fast & Slow may help |
|---|---|
| Find the middle of a linked list | FAST reaches the end while SLOW travels about half the distance |
| Detect whether a linked list loops back | Different speeds eventually meet inside a cycle |
| Find the beginning of a cycle | The meeting point can be used in a second phase |
| A sequence repeatedly produces another value | Treat each value as the next position in a sequence |
| Detect repetition with O(1) extra space | Cycle detection avoids storing every visited node |
| Find a node using the list's midpoint | SLOW can stop near the midpoint while FAST checks progress |

## Recognition decision tree

```text
Does the problem involve a linked list
or a sequence generated repeatedly?
                 |
                 v
Do you need the middle?
        |                |
       YES              NO
        |                |
        v                v
   Fast & Slow      Do you suspect a cycle
                    or repeated states?
                         |
                    YES  |  NO
                         |
                         v
                   Fast & Slow
                   may apply
```

**Warning:** These clues suggest the pattern; they do not guarantee it. Always check whether the pointer movement actually solves the problem.

# 3. THE FOUR MAIN PROBLEM FAMILIES

Most interview questions using this pattern fall into four families.

| Family | Main task | Typical example |
|---|---|---|
| A. Middle finding | Reach the midpoint efficiently | Middle of linked list |
| B. Cycle detection | Determine whether a loop exists | Linked List Cycle |
| C. Cycle entrance | Locate where the loop begins | Linked List Cycle II |
| D. Repeated transformation | Detect repetition in a generated sequence | Happy Number |

Learn the shared idea first, then understand what changes for each family.

---

# 4. FAMILY A — FIND THE MIDDLE

## When to recognize it

The question asks for:

- The middle node of a linked list.
- A midpoint without first counting all nodes.
- A node near the middle as part of a larger algorithm.

## Algorithm

```text
1. Start SLOW and FAST at head.
2. Move SLOW one node.
3. Move FAST two nodes.
4. Repeat while FAST and FAST.next exist.
5. Return SLOW.
```

## Java template

```java
ListNode slow = head;
ListNode fast = head;

while (fast != null && fast.next != null) {
    slow = slow.next;
    fast = fast.next.next;
}

return slow;
```

## What if the list has an even number of nodes?

```text
1 → 2 → 3 → 4 → null
```

Starting both pointers at `head` returns node `3`, the second middle.

If the question requires the first middle, the loop condition or initial pointer positions must be adjusted.

## Variations interviewers may ask

- Find the first middle instead of the second middle.
- Split a linked list into two halves.
- Find the midpoint before reversing part of a list.
- Check whether a linked list is a palindrome.

**Recognition rule:** If you need the middle without counting nodes first, think of Fast & Slow.

# 5. FAMILY B — DETECT A CYCLE

## When to recognize it

The question asks:

- Does the linked list contain a loop?
- Can traversal continue forever?
- Is a repeated state present?
- Can you detect repetition without using a HashSet?

## Algorithm

```text
1. Start SLOW and FAST at head.
2. Move SLOW one step.
3. Move FAST two steps.
4. If they point to the same node, a cycle exists.
5. If FAST reaches null, there is no cycle.
```

## Java template

```java
public boolean hasCycle(ListNode head) {
    ListNode slow = head;
    ListNode fast = head;

    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;

        if (slow == fast) {
            return true;
        }
    }

    return false;
}
```

## Why does it work?

Without a cycle, FAST eventually reaches the end.

With a cycle, FAST keeps moving around the loop. Because it moves one step farther than SLOW on each iteration, the gap between them eventually becomes zero.

## Variations interviewers may ask

- Detect a cycle in a linked list.
- Determine whether a pointer-based traversal terminates.
- Solve the problem in constant extra space.
- Explain why a HashSet solution uses more memory.

**Recognition rule:** If the question asks whether a loop exists, consider Floyd's cycle detection.

# 6. FAMILY C — FIND THE CYCLE ENTRANCE

This is a follow-up to cycle detection.

## When to recognize it

The question asks:

- Which node begins the cycle?
- Where does the list start looping?
- Return the node where the cycle begins, not just `true` or `false`.

## Algorithm: Two phases

```text
PHASE 1 — Find a meeting point.

Move SLOW one step and FAST two steps.
If they meet, a cycle exists.

PHASE 2 — Find the entrance.

Put another pointer at HEAD.
Keep SLOW at the meeting point.
Move both one step at a time.
Their next meeting point is the cycle entrance.
```

## Java template

```java
public ListNode detectCycle(ListNode head) {
    ListNode slow = head;
    ListNode fast = head;

    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;

        if (slow == fast) {
            ListNode start = head;

            while (start != slow) {
                start = start.next;
                slow = slow.next;
            }

            return start;
        }
    }

    return null;
}
```

## What you must understand

- The first meeting point is inside the cycle, but may not be its entrance.
- The second phase is necessary to locate the entrance.
- Both pointers in the second phase move one step at a time.

## Why does the second phase work?

Let:

- `a` = distance from the head to the cycle entrance.
- `b` = distance from the entrance to the meeting point.
- `c` = cycle length.

When FAST and SLOW meet, FAST has travelled twice as far as SLOW. This creates the distance relationship that makes moving one pointer from the head and another from the meeting point at the same speed bring them together at the entrance.

**Recognition rule:** If the question asks for the cycle's starting node, use cycle detection first, then the second phase.

# 7. FAMILY D — DETECT REPETITION IN A GENERATED SEQUENCE

## When to recognize it

The problem repeatedly transforms a value:

```text
value → transformation(value) → next value → ...
```

You need to determine whether the sequence reaches a target or repeats indefinitely.

## Example: Happy Number

```text
19 → 82 → 68 → 100 → 1
```

Each next value is the sum of the squares of the current value's digits.

If the sequence reaches `1`, the number is happy. Otherwise, it eventually enters a cycle that does not include `1`.

## General algorithm

```text
1. Define how to calculate the next value.
2. Set SLOW and FAST to the starting value.
3. Advance SLOW by one transformation.
4. Advance FAST by two transformations.
5. Continue until they meet.
6. Check what the meeting value means for the problem.
```

## Happy Number Java template

```java
public boolean isHappy(int n) {
    int slow = n;
    int fast = n;

    do {
        slow = sumOfSquares(slow);
        fast = sumOfSquares(sumOfSquares(fast));
    } while (slow != fast);

    return slow == 1;
}

private int sumOfSquares(int n) {
    int sum = 0;

    while (n > 0) {
        int digit = n % 10;
        sum += digit * digit;
        n /= 10;
    }

    return sum;
}
```

## What can change in a variation?

The transformation may change, but the cycle-detection idea remains the same.

For example:

- A number is transformed into another number.
- A state is transformed into another state.
- A deterministic process repeatedly produces a next state.

You must ensure that the sequence is deterministic and that the process eventually repeats or reaches a stopping condition. Fast & Slow is not automatically suitable for every repeated-state problem.

---

# 8. HOW TO CHOOSE THE POINTER MOVEMENT

Ask what the problem needs.

| Goal | SLOW movement | FAST movement |
|---|---|---|
| Find middle | One node | Two nodes |
| Detect a cycle | One node | Two nodes |
| Find cycle entrance | One node in phase 2 | Phase 2 uses another pointer moving one node |
| Happy Number | One transformation | Two transformations |

The movement is based on the algorithm. Do not change pointer speeds randomly.

---

# 9. FAST & SLOW VS HASHSET

Both approaches can detect a cycle, but they have different trade-offs.

| Approach | Time | Extra space | Main idea |
|---|---|---|---|
| HashSet | O(n) expected | O(n) | Remember every visited node |
| Fast & Slow | O(n) | O(1) | Detect a cycle using different speeds |

Use Fast & Slow when constant extra space is required or when you also need the cycle entrance.

A HashSet can be simpler to explain when memory is not a concern.

---

# 10. COMMON INTERVIEW FOLLOW-UPS

| Interviewer asks... | Key point to explain |
|---|---|
| Why not just use one pointer? | One pointer alone cannot determine the middle or detect every cycle this way |
| Why does FAST move two steps? | It gains one step on SLOW per iteration |
| Why compare nodes using `==`? | We need to know whether both references point to the same node |
| What if the list is empty? | Middle returns `null`; cycle detection returns `false` |
| What if the list has one node? | No cycle unless that node points to itself |
| Can the pointers meet at the cycle entrance? | Yes, sometimes, but not necessarily |
| Why reset one pointer to head? | This enables the second phase for finding the entrance |
| Can we solve it with a HashSet? | Yes, but it uses O(n) extra space |
| What is the time complexity? | O(n) for standard linked-list cycle and middle problems |

# 11. EDGE CASE CHECKLIST

Before submitting code, test:

- [ ] Empty list: `head == null`
- [ ] One node with `next == null`
- [ ] One node pointing to itself
- [ ] Two-node list without a cycle
- [ ] Cycle begins at the head
- [ ] Cycle begins in the middle
- [ ] Even-length list when finding the middle
- [ ] Odd-length list when finding the middle

# 12. HOW TO SOLVE AN UNFAMILIAR PROBLEM

Use this checklist in an interview.

```text
STEP 1 — IDENTIFY THE GOAL
Middle, cycle, cycle entrance, or repeated sequence?

STEP 2 — DEFINE THE NEXT STEP
What does one move mean?
Next node? Next transformed number?

STEP 3 — CHOOSE THE SPEEDS
Does SLOW move once and FAST twice?

STEP 4 — DEFINE THE STOPPING CONDITION
FAST reaches null? Pointers meet? Target reached?

STEP 5 — DEFINE THE ANSWER
Return SLOW? Return true/false? Run a second phase?

STEP 6 — TEST EDGE CASES
Empty input, one node, even length, cycle at head?

STEP 7 — STATE COMPLEXITY
Usually O(n) time and O(1) extra space for these problems.
```

| Problem type | Memory rule |
|---|---|
| Middle | FAST reaches the end; SLOW is in the middle |
| Cycle detection | FAST catches SLOW inside the cycle |
| Cycle entrance | Meet → reset one pointer → move both one step |
| Happy Number | Apply the transformation at two speeds |
